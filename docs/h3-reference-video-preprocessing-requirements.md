# H3 视频参考自适应低 Token 预处理需求

> 状态：需求草案
> 日期：2026-08-30
> 范围：MiniMax H3 Video Studio 服务端媒体派生、前端资产界面与 `h3ctl`

## 1. 背景

MiniMax H3 Ref2VA 会将文本、参考图像、参考视频、音频和目标视频打包成一条 Attention 序列。在 RTX 5090、RTX PRO 6000 等 `sm120` Blackwell 显卡上，当前 SageAttention FP8 内核在长序列下可能静默产生错误结果，表现为任务正常完成、无 CUDA 异常，但输出整段灰屏或马赛克噪声。

已有端到端验证表明：将 15 秒竖屏参考视频从 720×1280 预处理为 480×864、24 FPS 后，保持 15 秒、768×1344 目标输出和 Turbo 4 步可正常生成，不再出现灰屏。

本需求要将这一处理封装为 MiniMax H3 Video Studio 的可复用能力，而不是在 ComfyUI 工作流中隐式转码或写死单一分辨率。

## 2. 目标

1. 显式生成适用于 H3 Ref2VA 的低 Token 参考视频派生资产。
2. 保持源视频方向、宽高比、时间顺序和主要画面内容。
3. 前端与 `h3ctl` 调用同一服务端处理能力，产生一致结果和可审计回执。
4. 在生成前识别 `sm120 + SageAttention + 长序列` 风险，向用户给出明确警告和处理建议。
5. 不修改或覆盖用户原始素材。

## 3. 非目标

- 不在本功能中自动去除硬字幕、水印或标志。
- 不通过降低导出码率伪装成 Token 优化；必须真正降低 H3 编码时的参考画布尺寸。
- 不允许无进度事件、无回执记录地静默降低参考视频画质；服务端安全策略可自动生成派生参考，但必须对客户端可观测且不得改变目标输出尺寸。
- 不把预处理逻辑放入 ComfyUI 工作流图。
- 不将约 15 万 Token 视为所有显卡和 Attention 后端的通用硬上限。

## 4. 架构边界

预处理应位于 MiniMax H3 Video Studio 服务端媒体派生层，并由前端和 `h3ctl` 共用：

```text
前端 / h3ctl
    ↓
MiniMax H3 Video Studio 媒体派生 API
    ↓
prepare_h3_reference
    ↓
低 Token 派生视频
    ↓
ComfyUI Ref2VA 工作流
```

ComfyUI 工作流只读取处理后的媒体、编译 H3 节点并记录工作流证据，不再隐式改变参考尺寸。

## 5. 自适应尺寸算法

### 5.1 基本约束

- 保持原始方向和显示宽高比。
- 限制短边不超过 480 像素，长边不超过 864 像素。
- H3 输入画布宽高必须是 32 的倍数。
- 禁止拉伸。
- 默认禁止裁切。
- 原视频已小于限制时不放大画面内容。
- 必须先应用容器旋转元数据，再计算显示宽高和方向。

### 5.2 拟合与对齐

1. 根据源视频方向建立最大外框：
   - 横屏：864×480。
   - 竖屏：480×864。
   - 方形：480×480。
2. 将源画面按 `contain` 方式等比例缩放到外框内。
3. 将最终画布宽高对齐到 32 的倍数。
4. 对无法整除的少量边界使用最小填充，默认复制边缘像素，不使用明显黑边。
5. 回执必须同时记录内容区域和最终画布尺寸。

### 5.3 示例

| 源视频比例 | 典型源尺寸 | 预期画布 | 说明 |
| --- | --- | --- | --- |
| 9:16 | 1080×1920 | 480×864 | 竖屏，不转为横屏 |
| 16:9 | 1920×1080 | 864×480 | 横屏，不转为 480×864 |
| 1:1 | 1080×1080 | 480×480 | 保持方形 |
| 4:3 | 1440×1080 | 640×480 | 保持横屏 4:3 |
| 3:4 | 1080×1440 | 480×640 | 保持竖屏 3:4 |
| 21:9 | 2560×1080 | 约 864×384 | 长边受 864 限制 |

16:9 素材在 864×480 画布中应先等比例缩放到约 853×480，再对剩余的少量水平边界做边缘填充，不得直接拉伸到 864×480。

## 6. 媒体规范

- 帧率：24 FPS。
- 时长：最长 15.000 秒。
- 视频编码：H.264。
- 像素格式：YUV420P。
- 音频：用户必须显式选择 `keep` 或 `remove`；服务端不根据 Prompt 自行推测。
- 时长超限时必须在界面和回执中明示截断范围。
- 处理时使用临时文件和原子提交，失败或取消后不留下可被当作成品的半成品。

## 7. 服务端 API

在现有媒体派生能力中新增受控操作：

```text
prepare_h3_reference
```

请求示例：

```json
{
  "operation": "prepare_h3_reference",
  "source": "asset:SOURCE_ID",
  "max_short_edge": 480,
  "max_long_edge": 864,
  "fps": 24,
  "max_duration": 15,
  "audio": "remove",
  "fit": "contain",
  "alignment": 32,
  "pad_mode": "edge"
}
```

派生回执必须包含：

- 源资产 ID、内容哈希和显示名称。
- 原始宽高、旋转、帧率、帧数、时长和音频状态。
- 输出内容区域、画布宽高、帧率、帧数、时长和音频状态。
- 预处理算法版本和完整受控参数。
- 派生文件哈希、大小、MIME 类型和派生 ID。
- H3 参考视频 Token 估算和风险警告。

相同源内容哈希、相同算法版本与相同参数应可幂等复用已完成的派生结果。

## 8. `h3ctl` 交互

`h3ctl` 是该能力的薄客户端，对转码的具体实现无感：

- 不在运行 `h3ctl` 的本地机器上要求或调用 `ffmpeg`。
- 不读写服务器内部路径，只使用受控 locator 和 API 回执。
- 本地文件输入由 CLI 按现有上传合同流式上传，之后由服务端生成派生视频。
- 转码实现、尺寸计算、临时文件、幂等复用和失败清理均由服务端负责。

“实现无感”不等于“画质变更无感”。CLI 必须在请求、进度事件和最终 JSON 回执中明确表示是否执行了参考优化、原始与派生尺寸以及原资产与派生资产的映射。

新增原子命令：

```bash
h3ctl media prepare-reference asset:SOURCE_ID \
  --max-short-edge 480 \
  --max-long-edge 864 \
  --max-duration 15 \
  --audio remove
```

提供受控预设：

```bash
h3ctl media prepare-reference asset:SOURCE_ID \
  --preset h3-low-token
```

正常生成不增加任何 CLI 入参，现有命令合同保持不变：

```bash
h3ctl generate video \
  --mode r2v \
  --ref asset:SOURCE_ID \
  --duration 15
```

服务端在解析完实际 Profile、GPU 架构、Attention 后端、参考媒体和目标输出参数后执行风险预检。命中版本化安全策略时，服务端自动生成自适应派生参考并替换本次工作流绑定；CLI 不参与算法选择，也不需要新参数。

自动编排过程对 CLI 用户是一条原有生成命令，但对进度事件和最终回执必须可见：

```text
解析和上传原参考
  → 服务端风险预检
  → 需要时生成派生参考
  → 使用派生 locator 编译工作流
  → 提交生成任务
```

如预处理失败，生成任务不得提交；错误回执应包含可重试的阶段、请求 ID 和已物化的受控资源 locator，避免重试时重复上传或重复派生。自动预处理只能改变视频参考的派生副本，不得修改用户请求的目标时长、目标宽高、采样步数、模型或 Prompt。

命令应：

- 接受当地文件、`file:`、`asset:`、`job:` 和 `media:` locator。
- 返回稳定的 JSON/JSONL 回执和错误码。
- 默认返回 `media:DERIVATION_ID`，可直接作为生成参考，或通过 `media save` 保存到资产库。
- 本地输出不覆盖已有文件，除非显式传入 `--force`。
- 在 `ffmpeg` 不可用、媒体不可读、参数非法、磁盘不足或操作被取消时返回稳定错误。

## 9. 前端交互

在资产库视频菜单或参考绑定区域可提供提前物化派生资产的可选操作：

> 优化为 H3 视频参考（降低长序列灰屏风险）

用户确认前显示预计变化：

```text
原始：1920×1080 / 15.1 秒 / 30 FPS / 含音频
预计：864×480 / 15.0 秒 / 24 FPS / 移除音频
原始素材不会被修改
```

前端要求：

- 手动预处理操作必须由用户显式发起。
- 用户直接点击生成时不增加额外必填项；服务端命中安全策略后可自动派生，前端必须显示“正在优化视频参考”阶段和实际尺寸变化。
- 显示处理进度，支持取消和失败重试。
- 完成后将派生结果作为独立媒体展示，不替换或删除原资产。
- 用户可以预览、下载、保存到资产库或直接连接到生成节点。
- 刷新后能从派生回执恢复结果和参数。

## 10. Token 风险预检

生成请求应结合以下信息估算打包序列规模：

- 所有参考视频的实际编码尺寸和时长。
- 目标输出尺寸和帧数。
- 参考图像、Qwen 展示 Token 和音频序列的预留量。
- GPU 计算架构和实际 Attention 后端。

当检测到 `sm120 + SageAttention` 且估算总序列达到配置化风险阈值时，前端和 CLI 必须警告用户。首版默认警告阈值可为 150,000，但必须由版本化能力配置提供，不得散落硬编码在前端。

警告应提供可执行选项：

1. 生成低 Token 参考派生。
2. 降低目标输出尺寸。
3. 缩短参考时长。
4. 改用已验证的安全 Attention 后端。
5. 在用户明确确认后仍按原参数提交。

## 11. 工作流证据

生成任务应记录：

- 参考使用原资产还是派生资产。
- 原资产 ID 与派生 ID。
- 实际送入 H3 VAE 的宽高、帧率、帧数和音频状态。
- 预处理算法版本和参数摘要。
- 估算 Token、风险等级、GPU 架构和 Attention 后端。

这些字段用于复现、排障和后续阈值校准，不允许包含本地绝对路径、密钥或机器专属信息。

## 12. 错误与安全

服务端和 CLI 至少需要区分：

- `ffmpeg_unavailable`
- `media_probe_failed`
- `unsupported_media`
- `invalid_dimensions`
- `invalid_duration`
- `output_exists`
- `insufficient_storage`
- `media_processing_failed`
- `cancelled`

路径和资源解析必须复用现有安全边界，不允许客户端传入任意服务器输出路径。临时文件必须位于受控数据目录，并在成功、失败和取消路径上完成清理。

## 13. 验收标准

1. 1080×1920 竖屏素材派生为 480×864 画布，方向与主体完整。
2. 1920×1080 横屏素材派生为 864×480 画布，绝不转换成 480×864。
3. 1:1、4:3、3:4 和超宽屏素材按规则保持宽高比，不拉伸、不默认裁切。
4. 所有输出画布宽高均为 32 的倍数。
5. 手机旋转元数据不导致横竖屏判断反转。
6. 15.1 秒、30 FPS 视频可生成不超过 15.000 秒、24 FPS 的派生结果，回执记录实际截断。
7. 源文件始终保留，生成、失败、取消和重试都不得覆盖原资产。
8. 前端和 `h3ctl` 对相同源资产和相同参数得到相同派生哈希或复用同一回执。
9. 派生结果可预览、下载、保存为资产并直接用于 Ref2VA。
10. `sm120 + SageAttention` 风险预检在超过配置阈值时返回明确警告，不静默改参数。
11. 本次基准案例使用 480×864、15 秒参考和 768×1344、15 秒目标输出时，Turbo 4 步生成不出现整段灰屏。
12. 中断、媒体错误或磁盘不足时不留下可被当作完整产物的半成品。
13. 现有 `h3ctl generate video` 命令和 operation schema 不增加参考优化入参；是否优化由服务端版本化安全策略决定。

## 14. 测试要求

### 14.1 单元测试

- 方向、旋转元数据和宽高比分类。
- 尺寸外框、`contain` 缩放、32 倍数画布和最小填充计算。
- 小视频不放大。
- 时长上限、帧率和音频模式验证。
- 幂等键和派生回执序列化。
- Token 估算与风险阈值判定。

### 14.2 集成测试

- 使用小型横屏、竖屏、方形、超宽屏和带旋转元数据 fixture 执行 `ffmpeg`。
- 通过 `ffprobe` 复核输出尺寸、24 FPS、时长、帧数、编码和音频状态。
- 验证 API、前端客户端和 `h3ctl` 的合同一致性。
- 验证取消、失败清理、原子提交和重复请求复用。

### 14.3 端到端测试

- 前端：上传源视频，查看预计变化，发起处理，刷新恢复，保存派生资产并连接到视频生成节点。
- CLI：对同一资产执行 `media prepare-reference`，获取派生 locator，提交 Ref2VA 生成并下载结果。
- H3：使用已验证的 15 秒竖屏案例复测整段非灰屏、首尾帧可视和媒体元数据完整。

## 15. 交付顺序

1. 服务端尺寸算法、媒体派生操作、回执和测试。
2. `h3ctl` 原子 operation、人类命令、JSON 合同和测试。
3. 前端显式预处理交互、进度、恢复和派生结果绑定。
4. Token 风险预检、版本化阈值和工作流证据。
5. 完整端到端复测、LLM Wiki 同步与发布准备。
